# Local audit-polarity experiment — 18 October 2026

## Decision

The audit-only candidate is promising for a reviewed source update. Do not deploy it solely from this experiment. The official team Alibaba transport and a hosted preview have not been rechecked. The existing website, public repository and teammate code remain unchanged.

## What changed

Generation remains extract-v2.28 with byte-identical generation instructions. Only the internal source audit advances from context-audit-1.7.0 to 1.8.0: read full-clause negation before choosing retrospective denial, distinguish cancellation from denial, and keep actual denials, repayment promises, original loan requests and correct event targets mandatory. A separately versioned local overlay records this change. No audit finding is filtered, no row is rewritten, and strict rejection remains in place. Frontend, public schema 2.0.0, budgets, provider, frozen gold and original score records are unchanged.

## Real private-gateway checks

The five paired audits received identical original source/draft payloads; only the audit system instruction differed. Correct cancellation-without-denial and normal company funding were accepted by both old and new audit in this run. A draft that incorrectly represented a genuine denial as a withdrawal was wrongly accepted by the old audit and rejected by the new audit. Both audits rejected omitted cancellation and an omitted first repayment promise. These are audited draft controls, not five fresh end-to-end generations.

The candidate then completed the full complex RR06 flow twice (42.283 and 43.023 seconds), retaining the two applicant loan operations, typed promise for both, non-denying withdrawal, literal citations and original chronology. The company-funded full control completed in 46.913 seconds without a false personal-payment warning. All complete outputs were reviewed field by field, beyond final guidance.

The old false-refusal observation remains valid historical evidence, but its fresh same-draft replay passed this time. Therefore this experiment does not prove the refusal is eliminated or that overall accuracy improved. Two identical successful repeats are one exposed case repeated, not independent validation; correlated/cached responses are not independent evidence.

## Verification and billing

360 integration checks, 93 compatibility checks and a Next.js Webpack production build including TypeScript passed. Three new checks include effective versioned audit dispatch and unchanged rejection of findings. The original producer/gold fixtures remain unchanged.

16 raw requests; 37,596 input tokens + 13,648 output tokens = 51,244 recorded tokens. No retry, unknown-usage request or model switching. Actual private-gateway pricing is unverified. No team Alibaba allowance or real account trial allowance was used.

The original experiment harness produced five baseline setup failures before any outbound request because it passed a candidate-module library instance to the baseline module. Those errors are retained locally and excluded from model quality. Only the baseline loader was corrected for the first five real baseline requests; candidate results were not retried or replaced.

## Handoff

Use [the machine-readable complete review](audit-polarity-verification-2026-10-18.json). The isolated local experiment retains the full baseline/candidate and proposed-file hashes. Do not copy credentials, .local-data, node_modules or build output. Do not overwrite a teammate's newer edits. A later source update should add this dated evidence; it must not rewrite the old v28 experiment or claim ninety-percent accuracy.

Before production adoption, recheck the same complex input and normal company-funded control on the official team Alibaba json_schema path and an isolated preview. Current 42-47 second latency leaves little margin under the existing 50-second model budget. Neither model-quality claims nor browser-format guarantees come from a successful build alone.
