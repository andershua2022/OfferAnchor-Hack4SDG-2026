## Initial historical real complex test (v2.11)

One authored fictional request was frozen with ten expectations before the call. It combines a normal payroll request, an explicit credential-sharing prohibition, personal borrowing plus transfer as a condition of work, an unverified repayment promise, a later denial and a source-embedded instruction to mark the offer safe. It is not an actual victim conversation, official company policy, untouched held-out case or independent accuracy dataset.

- Provider/model: official Alibaba Model Studio, China Beijing, qwen3.8-max.
- Same production createWorkspaceApi/post, source-bound provider, extract-v2.11 and contract 2.0.0 were used in an isolated one-call handler harness. This was not a full browser-to-provider HTTP trial.
- One model request, zero retries, unchanged live disabled setting in the running application.
- Provider HTTP 200, finish_reason stop; application HTTP 502, status incomplete, errorCode invalid_output.
- Observed time: 18,646 ms. Input: 2,849 tokens; output: 933; total: 3,782; reported cached input: 0.
- Official Beijing list rate checked on 18 October: CNY12/million input and CNY36/million output. Estimated inference fee: (2849*12 + 933*36)/1,000,000 = CNY 0.067776, about CNY 0.068. This is an estimate, not an inspected invoice or proof of a charge. No image/search fee was incurred by this probe.
- Price source: [Alibaba qwen3.8-max model page](https://help.aliyun.com/zh/model-studio/qwen3-8-max).

The raw output correctly retained applicant borrowing and borrowed-fund transfer, ordinary payroll information, repayment as a stated promise, the later denial and its contradiction, and all seven literal quotations. It did not obey the embedded classify-safe instruction. However, its prohibited credential action used verb other with account_control/credential_control. The unchanged semantic contract requires share_otp or share_account_details for that mechanism, including prohibited actions. It therefore failed the mechanism rule before guidance/reference selection. The product correctly withheld a result and export, but safe refusal is not successful task completion.

The end-to-end result for this case is **not passed**. Do not turn the individually correct raw observations into an accuracy percentage. No prompt, validator, model or result was silently repaired to manufacture a pass. The later candidate v2.13 resolves this particular tuple but fails other predeclared/source-backed checks; see the dated follow-up. Broader untouched evaluation is still needed.

## Security correction from this review

The Google callback previously flushed exchange-created cookies even when the final getUser step failed. Failed callbacks now publish no provisional cookies; successful callbacks require the final identity to match the exchanged identity. Synthetic regressions cover identity-service/network failure, missing/wrong user and preservation of a previously valid browser session. The new five cases failed before the patch and passed after it; real personal consent was not replayed.

## Deployment boundary

A complete Node application is required; static-only hosting cannot run the API. The shareable source package deliberately excludes .env.local, private logs, .git, node_modules, .next and caches. Populate host secrets privately; no user supplies a model API key. Keep the pinned Node/npm/lockfile, build with dev dependencies, and retain all public assets/licenses plus contracts, examples, knowledge, locales and the imported project manifest.

**Historical hosting guidance, superseded for shared state:** the shared Supabase auth/quota coordination layer is now implemented and passed its 34-check/61-request isolated verification; deployment and hosted auth acceptance remain pending. Keep the exact `APP_ORIGIN`, Supabase `/auth/callback` allowlist and existing Google callback, then verify sign-in/logout on the deployed host. Current route budgets and limits are documented in [Vercel preparation](vercel-deployment.md). Cloud logs must not capture submitted documents or credentials.

Before unrestricted public live release: resolve the known model failure and independent effectiveness gates; finish required essential UI localization and real-device acceptance; use tested shared/host controls for quotas/challenges and actual spending protection; verify production-domain auth, sender capacity and processor/hosting notices. No universal delivery, fraud detection accuracy or employer safety guarantee is made.
