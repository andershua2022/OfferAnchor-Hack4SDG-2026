## Two different privacy responsibilities

P0-07 protects the user's submitted evidence and the processing/export workflow for every intended user. EXT-01 would analyse whether a recruiter is requesting personal data with unresolved purpose, identity, channel or recruitment stage. Baseline 2.2 adds no general personal-data classifier or mandatory binary API. D23 permits optional local file-to-reviewed-text convenience while retaining the same analysis contract. An absence of financial/account demands cannot be reported as privacy clearance. Use fictional/redacted wording, not actual identity-card images or complete credentials, for future development. [PRD coverage/gates](PRD.md#31-current-coverage-and-conditional-extensions) governs activation.

## 1. Data inventory and permitted storage

| Data | Planned location | Boundary |
|---|---|---|
| Selected evidence/notes | Page memory; transient server request; live model processor | No product evidence database; preview/edit before submission |
| Raw provider output | Transient live server processing | Never public/UI/logged; synthetic evaluation archive only |
| Canonical extraction/brief draft | Page memory; transient response | Clear/end removes app state, not all processor traces |
| Exported snapshot | User-controlled clipboard/print/destination | Cannot be recalled; locked footer retains mode/boundary |
| API key/access code/signing secret | Server environment | No client bundle/source/URL/log |
| Operational telemetry | Sanitized server/host metrics | Opaque attempt, code, timing/usage only; no raw evidence |
| Consent/contact/optional recording | Ignored private research storage | Restricted access; separate from anonymous task scores |
| Synthetic fixtures/locale/library | Git | No real accounts, private chats, secrets or fabricated approval |

Page memory is not proof that nothing leaves the device. Live analysis uses an external processor. No Hong Kong-only processing, zero retention/training or secure erasure claim without provider/host evidence. A provider may process/bill after browser cancellation.

## 2. Input, notices and sensitive-processing gate

Before analysis show the selected text, current processor identity/handling and session/export boundary. Encourage removal of complete bank/ID numbers, passwords, OTPs, addresses and unrelated third-party detail. Preserve enough fictional/redacted wording to understand the action; redaction is not anonymization. No automatic-redaction claim.

Only fictional/redacted material is permitted while processor/host handling is unresolved. Real messages are optional and must not be required for a persuasive demonstration. The default student pilot uses fictional tasks, with separate research consent and no real financial action.

Before sensitive live input, record actual account tier, key class, model/version, region/geography, retention/training terms, logging/debugging, subprocessors, deletion options, URLs/check date and reviewers. An unknown is a blocker to that trial. A region picker or framework default is not the complete data lifecycle.

PCPD's 25 August agentic-AI publication informs bounded access/human oversight; it is not certification. Earlier direct-page review and 5 October index reconfirmation are separate source observations; intermittent direct access remains recorded. ## 3. Threats, controls and observations

| Threat | Required control | Check |
|---|---|---|
| Source tells model to approve/send funds | No execution tools; source is data; application-owned policy | Hostile/multilingual inputs, no permission change |
| Real quote receives wrong interpretation | Separate semantic labels/correction; no truth badge | Actor/polarity/mechanism/claim controls |
| Fabricated or wrong quote occurrence | Exact raw occurrence resolver plus canonical validation | Missing/duplicate/overlapping/emoji/source cases |
| Model invents contact or execution link | No route fields in extraction; approved ID resolution only | No model-generated actionable route |
| Submitted suspicious URL is visited | Text-only/inert rendering; no automatic preview/fetch | Network audit for submitted host |
| Scripts execute from text | Plain text rendering; no raw HTML/linkification | HTML/script/instruction payload stays inert |
| Provider secret leaks | Server-only config, sanitized failures/logs/bundle check | No secret in UI/response/source/bundle |
| Shared demo access burns budget | Same-origin gate, atomic limits, global cap/kill switch | Unauthorized/quota denied before provider |
| Another user's result appears | No shared result cache; no-store; request/revision isolation | Concurrent independent payloads |
| Old response replaces correction | Active run/revision and 30-second outer deadline | Edit/cancel/supersede/background resume |
| Incomplete response appears successful | Typed API/reducer mapping; only complete activates | All transport/API errors and malformed body |
| Private content remains in logs | No request/response logging; host review | Synthetic sentinel absent from logs |
| Edited export loses caveat | Locked product/version/mode/boundary footer | Copy/print retain footer and edit notice |
| Browser restores working data | Clear state and actual lifecycle tests | Back/forward/reload/background; record limitations |

OWASP describes direct/indirect prompt injection. Limiting tools reduces consequences; it does not prove the model never follows hostile text. [OWASP LLM01](https://genai.owasp.org/llmrisk/llm01-prompt-injection/).

## 4. Financial, interpretation and verification limits

Never recommend the scoped borrowing/task recharge/transfer/control demand, authenticate an employer, guarantee repayment/recovery or determine legal/credit liability. Company existence, recruiter authorization and instruction legitimacy are separate. Ordinary payroll or expense wording does not establish safety.

Mechanisms and relationships are model inferences with evidence, not independent facts. Exact quote resolution is deterministic; actor/polarity/meaning remains semantic. Later denial cannot erase prior supported danger; preserve conflict. Identity/repayment uncertainty alone is context, not a financial-demand finding.

ADCC 18222 is 24-hour consultation, not a product verification/reporting API. Do not use fictional calls/reports in tests. Banking help means the user's independently obtained contact. [Official ADCC scope](https://www.adcc.gov.hk/zh-hk/contact-us.html).

All outreach is user initiated. A copied brief, opened route, print dialog, user-reported reply or claimed bank contact does not prove delivery/contact/verification. Selected original evidence and edited draft body retain different labels.

## 5. Access, quota and time controls

Operational defaults are specified in [setup-and-operations](setup-and-operations.md): two-hour demo credential, same-origin POST, 96 KiB body, credential/global concurrency and windows, 25/28/30-second provider/server/browser budgets. Shared access is cost control, not personal accounts.

A shared access code does not identify individuals. Per-credential controls apply to the issued credential/cohort; new browser cookies must not silently reset a shared budget. Atomic shared storage or equivalent host protection is required for distributed deployment. Process-local limits are restricted to documented single-process controlled tests.

Simulation makes no paid calls regardless of `MODEL_CALLS_ENABLED`. Live false/missing config returns incomplete. Provider account spend limits remain a separate unverified gate; no purchase or spend authorization is implied. Abort does not refund a call; count failed/truncated requests.

## 6. Clear-session, lifecycle and exports

Clear-session resets working evidence/result/questions/draft references and aborts active UI work. Working evidence and original attachments are not automatically persisted. Explicitly saved simulation copies use plaintext localStorage; demo preferences may use sessionStorage. Account tokens are HttpOnly cookies, not JavaScript storage. No cloud history or service-worker evidence cache is enabled. Signing out closes working material; previously browser-saved copies require separate deletion. Do not promise secure memory wiping, deletion of host/provider logs or recall of exported copies.

Evidence/locale changes invalidate current analysis and its export eligibility. An editable body cannot remove the application-controlled footer. An already exported snapshot remains external and cannot become current automatically.

Test actual iOS/Android back-forward restoration, background/resume, reload, copy/print and cancellation. Report browser limitations. Future persistence needs new access/consent/deletion decisions; no silent caching workaround.

## 7. Release review

CS/AI provide observed checks; different reviewers inspect them. Required: approved localized library/routes; processor gate appropriate to input; keys hidden; verified access/atomic limits/kill switch; no raw logs; exact citations and semantic controls; safe transport/incomplete states; no stale replacement; inert rendering; usable clear/export; actual phones.

One observed dangerous recommendation, invented active contact, stale replacement, secret/raw-evidence leak or absence of the working core blocks release. Documentation and synthetic expectations are not privacy certification or effectiveness evidence.
