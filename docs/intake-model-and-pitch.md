## 1. What a file contributes

An attachment supplies selected words, not proof of an employer, signature or document authenticity.

| Format | Current canonical preparation | Limits |
|---|---|---|
| TXT / Markdown | Local UTF-8 decoding as plain text | No HTML execution, external links or embedded image fetching |
| DOCX | Local bounded Word-text extraction | Formatting and embedded images are not reproduced; complex text needs review |
| Text-only PDF | Local pinned PDF.js extraction | At most ten pages; reading order can be imperfect |
| PNG / JPEG / WebP | Local preview/re-encoding, then optional cloud transcription | Explicit consent; at most 2 MB after encoding and 4,194,304 pixels |
| Scanned / mixed PDF | Render all pages locally, then transcribe each selected document page | At most two pages for this path; each page uses one call; no original PDF upload |
| DOC / DOCM / other formats | Not supported | Save as DOCX or paste the relevant words; no macros |

Four attachments maximum, 5 MB per chosen file and 15 MB combined. Extraction can produce at most 24,000 characters for selection, but final evidence remains **4,000 UTF-16 units per source, 12,000 total and eight allocated IDs**. Long text needs editing, not silent truncation. These bounds are not a production file-security audit. DOCX has separate ZIP expansion/worker bounds.

## 2. One visible composer, separate sources

1. Attach files with the circular paperclip. Files stay above the text input; selecting a file makes no cloud request.
2. Successful short local document text is immediately usable. For an image or scanned/mixed PDF, open its chip and choose Read image / Read PDF pages. A separate dialog explains the whole-image transfer before any OCR request.
3. Typed supplementary text is optional. Preview, redaction, source-type selection and editing remain available. Unclear, empty, failed or overlong text needs correction/confirmation; do not invent successful reading. Editing extracted text requires confirming that edit.
4. Check request sends separate text evidence entries to the existing analysis route. One attachment can supply the latest instruction by itself. An attachment deliberately classified only as an earlier offer still needs a current instruction.
5. Committed chips remain in page memory. Rechecking does not append duplicate evidence. Removing a committed chip removes its source and retires the result. New check, replacement, sign-out and leaving release local attachments. Original binaries are not added to history.

Canonical quotations are exact to the extracted/edited source text, not guaranteed exact to image pixels. Machine-read text is labelled as unverified. Optional editing is not authentication.

## 4. Privacy, API and implementation

The canonical route **POST /api/intake/image** accepts a strict versioned request, explicit consent and one inline image. It rejects remote URLs, filenames, unsupported formats, invalid dimensions and extra fields. The browser strips original metadata by re-encoding; PDF pages are rendered locally. The existing origin, signed demo access, approved library and shared paid-attempt limits also protect OCR. Feature-off/simulation does not contact a model. No automatic retries, tools, source-link visits or raw provider error disclosure.

The existing **POST /api/analyze** remains text-only. Image reading can expose private details anywhere in the whole image, even if omitted from the extracted text later. Crop/redact before consent or enter text instead. The notice must identify Alibaba Cloud China (Beijing) and distinguish project memory from provider processing/retention. Do not promise absolute secrecy or zero provider retention.

Use the [runtime record](connected-workspace-2026-10-17.md) for current activation. Product cloud accounts/history, independent participant acceptance and public deployment remain pending. A clean clone defaults to simulation and needs private server configuration to activate paid services.
