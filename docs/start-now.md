## One-time setup

1. Clone the private [shared repository](https://github.com/andershua2022/OfferAnchor) and use `main` containing this guide and the standing grant. Preserve existing local work. Record the actual commit; the manifest's older parent anchor is not a reset command.
2. Identify your own profession: CS, AI-DS, DASE, Design or Communication. Use the corresponding guide in [resources](publication-scope.md#excluded-material); no personal names, new AI/DS permission or paid API key is needed for the first stage.
3. Give your sole primary writing agent the role guide and [agent-start.md](publication-scope.md#excluded-material). Check the role issue for an existing executor, record your actual session/branch/base/intended files, and begin. Recording is a status notice, not an approval request. If issue posting is unavailable, keep that record in the agent handoff and start the already approved independent work; reconcile the same issue when access returns.
4. Use one writing agent per profession. A second agent for that member is read-only. Keep one profession branch, inspect changes before switching, and never create a second app, extractor or source library.

## Keep going within your assigned work

After the first handoff, continue your `authorizedOwnerPackages` sequentially in the same sole-primary-agent scope. Choose ordinary implementation details yourself within the PRD/interfaces and current package paths. Your role owns its reserved public/private paths; other professions do not write there. List concrete changed files in the same issue/handoff. New files inside an already reserved owner/package subtree do not need AI/DS reapproval; unlisted paths or another owner's files require the owner/change procedure.

When a later step needs another role's accepted artifact, request that artifact through its existing role issue, preserve the shared interface and continue independently permitted preparation. Do not ask the representative to restate this grant, build a competing module, pretend a mock is live, or mark a prerequisite accepted yourself. Reviewers and consumers inspect; only the owner fixes its files. Independent annotation, recruitment preparation, device review and graphics support are narrowly listed in `startupGrant.supportingWork`.

This standing grant approves local implementation and checks. It does not authorize later teammate Git commits/pushes/PRs without their own task-level authorization, a main merge, deployment, purchases, paid model calls or messages to external recipients. A teammate can authorize its agent's task-branch delivery; it need not ask AI/DS for routine code choices. No real user text, credentials or identifiable participant material belongs in Git. Existing personal AI experiments stay separate; CS receives only an explicitly shared, reviewed implementation.
