## 3. One canonical library and one displayed string source

[knowledge/library.json](../knowledge/library.json) is the sole card/route/source content file. Future `lib/knowledge/*` is loader/validator/selector code, never a copied second library. The global `libraryVersion` covers every source, card and route; no separate per-card version is implied.

Card metadata includes stable ID, title, tags, dangerous relationships, benign controls, suggested questions, route/source IDs, check date and approval. Route metadata includes stable ID, service type, official URL/telephone where relevant, scope, source and approval. Editorial titles/questions/synthesis in the library are English developer material.

Actual displayed card/route text comes from [en-HK.json](../locales/en-HK.json) and [zh-Hant-HK.json](../locales/zh-Hant-HK.json), keyed by the same stable IDs. Design owns keys; Communication reviews equivalent meaning. Do not silently show an English library field when a translation is missing, translate it at runtime with a model, or create a third independent copy. Missing required localized text blocks the affected live display/release.

The library and authored locale artifacts are draft. Research-agent checking is not named human approval. Approval covers the selected card/route and both locales together; version all meaning changes and rerun affected cases. Do not invent a reviewer name or mark approval because an agent wrote the text.

## 4. Starting cards and their role

| Stable ID | Role |
|---|---|
| `K_TASK_RECHARGE` | Advance payment to unlock work/tasks/earnings; prior small commission is not validation |
| `K_PERSONAL_BORROWING` | Own-name borrowing/nominated transfer; recruiter repayment remains a claim |
| `K_COMPANY_PAID` | Company-funded work/prohibition contrast; identity unresolved |
| `K_PAYROLL` | Ordinary payroll details versus requested OTP/account control |
| `K_UNKNOWN` | Relevant missing/conflicting action context; independent clarification |
| `K_ALREADY_ACTED` | User-reported action; independently obtained bank/police help, no recovery promise |
| `K_ORDINARY_EXPENSE` | Ordinary reimbursable expense control; funding/reimbursement/safety unconfirmed |

Cards are source-inspired product synthesis, not verbatim official findings about a submitted job. The ordinary-expense card prevents every work expense from becoming a task scam; it is not permission to pay or a guarantee of reimbursement.

AI selects cards/routes only through the [frozen policy table](integration-contract.md), using cited structured actions/unknowns. No keyword detector or model-supplied contact. Identity/repayment uncertainty does not automatically activate a financial warning. A later denial preserves earlier supported danger and the contradiction.

## 5. Route approval and source changes

Every route must resolve to the reviewed official URL/telephone and scope in the canonical library. ADCC consultation is not an authentication API; a company search is not recruiter authorization; no-record Scameter results are not safety.

Bank help uses the user's independently opened bank app/card contact, never a submitted number. Suspicious input links remain inert; no preview fetch. Official routes are opened only by a user action. Copy, print, opening a route or a reported conversation never becomes confirmed delivery/verification.

Communication records original-source access, check date, scope and human reviewer. Recheck changing contacts/provider terms before freeze. A source that becomes unavailable may stay in the historical ledger but cannot silently support a current stronger claim. Approval withdrawal disables the affected card/route for live selection and triggers a versioned review.

## 6. Synthetic cases and evaluation separation

Construct fictional messages preserving the relevant relationship, then vary style/names/amounts. Record author, source inspiration and synthesis status. Add company-paid prohibitions, ordinary expenses, payroll controls, missing payer, promises, conflicting replies, embedded attacks and Unicode/repeated quotes.

Keep translations/paraphrases of a base case in the same partition. Public examples and development cases are not held-out evidence. DASE freezes independent labels and split hashes before prompt tuning. Do not let an authored expected response become a model result.

Raw synthetic provider output and canonical resolved results are stored separately in ignored evaluation storage; public fixtures must stay synthetic and secret-free. Participant contact/consent/recordings are separate private records. The JSON/CSV templates are formats, not observations.

## 7. Handoff and acceptance

Communication delivers approved versioned library/source ledger and bilingual meaning review to AI/Design. AI delivers deterministic selection plus route validation to CS. DASE delivers grouped annotations/splits. All roles use the same IDs and version.

Accept when source/card/route references exist, approvals and locale keys agree, no invented contact is displayed, benign controls remain distinct and all selected routes carry their scope. Store reviewed claims and unresolved source problems in [status](status-and-evidence.md); blank human-review fields remain blockers, not completed work.
